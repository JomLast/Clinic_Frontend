โดยอีเมลยังส่งเหมือนเดิมไว้เป็นหลักฐานย้อนหลัง — ไม่ได้ตัดทิ้ง

## ทำไมต้องมีตัวกลาง ทำไมยิงจากหน้าเว็บตรง ๆ ไม่ได้

การส่งข้อความในนามคลินิกต้องใช้ *Channel access token* ถ้าเอาไปวางไว้ในหน้าเว็บ
ใครกดดูโค้ดหน้าเว็บก็เห็น แล้วส่งข้อความหาลูกค้าทุกคนในนามคลินิกได้ทันที
จึงต้องมีตัวกลางฝั่งเซิร์ฟเวอร์ถือ token ไว้ — `worker.js` คือตัวกลางนั้น

ใช้ Cloudflare Worker เพราะคลินิกมีบัญชี Cloudflare อยู่แล้ว ทำในหน้าเว็บล้วน ๆ
ไม่ต้องลงโปรแกรม ไม่ต้องใช้ command line **และไม่ต้องรอระบบสมาชิกที่จะได้ใช้ปีหน้า**

## ขั้นที่ 1 — สร้าง Messaging API channel

ใน [LINE Developers](https://developers.line.biz/console/) → Provider **Asiapet** ตัวเดิม
→ Create a new channel → **Messaging API**

> **อย่าสร้าง LINE OA ใหม่** ให้เชื่อม OA เดิมของคลินิกเข้ามา ไม่งั้นเพื่อนที่มีอยู่จะไม่ตามมา
>
> และต้องอยู่ใน Provider **เดียวกัน** กับ LINE Login channel ไม่งั้นรหัสผู้ใช้จะไม่ตรงกัน
> ตอนทำระบบสมาชิกปีหน้า แล้วย้ายทีหลังไม่ได้ ต้องรื้อสร้างใหม่

จากนั้นแท็บ **Messaging API** → **Channel access token** → กด Issue → ก๊อปเก็บไว้

## ขั้นที่ 2 — เปิดให้บอทเข้ากลุ่มได้

ที่ **LINE OA Manager** → ตั้งค่า → การตอบกลับ

| ตั้งเป็น | เหตุผล |
|---|---|
| อนุญาตให้บอทเข้ากลุ่ม → **เปิด** | ค่าเริ่มต้นปิดอยู่ ถ้าไม่เปิด เชิญบอทเข้ากลุ่มไม่ได้เลย |
| ข้อความตอบกลับอัตโนมัติ → **ปิด** | ไม่งั้นบอทจะตอบทุกครั้งที่มีคนพิมพ์ในกลุ่ม รำคาญมาก |
| Webhook → **เปิด** | ใช้หา ID ของกลุ่มในขั้นที่ 4 |

## ขั้นที่ 3 — สร้าง Worker ใน Cloudflare

[dash.cloudflare.com](https://dash.cloudflare.com) → **Workers & Pages** → Create → Worker

1. ตั้งชื่อ `asiapet-line-notify` → Deploy (ตอนนี้ยังเป็นโค้ดตัวอย่าง ไม่เป็นไร)
2. กด **Edit code** → ลบของเดิมทิ้งทั้งหมด → วางเนื้อหาไฟล์ `worker.js` ลงไป → Deploy
3. **Settings → Variables and Secrets** → เพิ่ม 2 ค่า **กด Encrypt ทั้งคู่**

| ชื่อ | ค่า |
|---|---|
| `LINE_CHANNEL_ACCESS_TOKEN` | token จากขั้นที่ 1 |
| `TARGET_ID` | ใส่ `x` ไปก่อน เดี๋ยวขั้นที่ 4 ค่อยแก้ |

4. จด URL ของ Worker ไว้ หน้าตาแบบ `https://asiapet-line-notify.xxxx.workers.dev`

> Encrypt สำคัญมาก ถ้าไม่กด ค่าจะโชว์เป็นตัวอักษรธรรมดาให้ทุกคนที่เข้าหน้านี้เห็น

## ขั้นที่ 4 — หา ID ของกลุ่ม

1. กลับไป LINE Developers → แท็บ Messaging API → **Webhook URL** ใส่

   ```
   https://asiapet-line-notify.xxxx.workers.dev/line-webhook
   ```

   แล้วเปิด **Use webhook**

2. สร้างกลุ่มไลน์ของพนักงาน เช่น *จองคิวเอเชียเพ็ท* แล้ว **เชิญ OA ของคลินิกเข้ากลุ่ม**
3. พิมพ์อะไรก็ได้ในกลุ่มสักคำ — **บอทจะตอบกลับมาเองว่า ID ของห้องนี้คืออะไร**
   ขึ้นต้นด้วยตัว `C`
4. เอา ID นั้นไปแก้ค่า `TARGET_ID` ใน Cloudflare แล้วกด Deploy อีกครั้ง

> ทำแบบนี้เพื่อไม่ต้องไปงมหา ID ในหน้า dashboard ที่ไหน บอทบอกให้ในกลุ่มเลย
>
> เสร็จแล้ว **ปิด Use webhook ได้** ใช้แค่ตอนหา ID เท่านั้น

## ขั้นที่ 5 — ต่อเข้าหน้าเว็บ

ส่ง **URL ของ Worker** มาให้ผม (ไม่ใช่ความลับ) ผมจะใส่ลงในหน้า `contact.html`
ตรงค่า `LINE_NOTIFY_URL` ที่เตรียมไว้แล้ว แล้ว push ให้

ตอนนี้ค่านั้นเว้นว่างอยู่ ซึ่งแปลว่า**ยังไม่มีคำขอออกไปหาที่ไหนเลย** เว็บทำงานเหมือนเดิมทุกอย่าง

กรอกฟอร์มจองที่ `asiapethospital.com/contact.html` ด้วยข้อมูลสมมติ
ควรเด้งเข้ากลุ่มไลน์ภายในไม่กี่วินาที หน้าตาแบบนี้

## เรื่องที่ควรรู้ไว้

**โควตาข้อความ** — ข้อความแบบ push นับรวมในโควตารายเดือนของ LINE OA
(ส่วนข้อความที่บอท *ตอบกลับ* ไม่นับ) ใบจอง 1 ใบ = 1 ข้อความ ต่อให้ในกลุ่มมี 10 คน
ปริมาณระดับใบจองต่อเดือนจึงถือว่าน้อยมาก แต่โควตาก้อนนี้ใช้ร่วมกับการบรอดแคสต์
โปรโมชั่นด้วย ถ้าเดือนไหนยิงโปรฯ เยอะ ควรเช็คโควตาที่เหลือใน OA Manager

**กันคนยิงมั่ว** — Worker รับเฉพาะคำขอที่มาจาก `asiapethospital.com` เท่านั้น
มีกับดักบอทในฟอร์มอยู่แล้ว และตัดความยาวทุกช่องก่อนส่ง ถ้าวันหนึ่งเจอคนยิงถี่ ๆ
เพิ่ม **Rate limiting rule** ใน Cloudflare ได้อีกชั้น เช่น จำกัด 5 ครั้งต่อ IP ต่อนาที

**ถ้าอยากให้เข้าไลน์ส่วนตัวแทนกลุ่ม** — ขั้นที่ 4 เปลี่ยนเป็นทักบอทตรง ๆ แทนการเชิญเข้ากลุ่ม
บอทจะตอบ ID ที่ขึ้นต้นด้วย `U` เอาไปใส่ `TARGET_ID` เหมือนกัน
แต่แนะนำเป็นกลุ่มมากกว่า เพราะถ้าคนคนเดียวลาหยุด ใบจองจะไม่มีใครเห็น
